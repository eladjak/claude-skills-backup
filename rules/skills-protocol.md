## During Work: Insight-Driven Skill Evolution
While implementing, actively notice:
- Friction points → candidate for new skill or skill upgrade
- Repeated patterns → codify into a skill with clear triggers
- Better approaches → upgrade existing skill with the improved method
- Cross-project insights → propagate to global skills/rules

## End of Iteration: Self-Improvement Check
Every iteration, before delivering the review document:
1. **Tools audit**: What skills/MCPs/agents could I have used but didn't?
2. **Learning**: What patterns did I discover that should be saved for future sessions?
3. **Efficiency**: Did I parallelize enough? Could I have launched more agents?
4. **Quality**: Did I use skills (rams, dogfood, hebrew-rtl) to validate work?
5. **Save learnings**: Update memory with new patterns, tools, or preferences discovered
6. **Skill impact**: Did I create or upgrade any skills? If not, was there an opportunity I missed?
7. **Growth delta**: What did I do BETTER than the previous iteration? What will I push on next?
8. **Agent improvements**: Should any agent's prompt or capabilities be upgraded based on this session?

## Rule
Don't just implement — validate with the right skill first. Launch skill-powered agents in parallel with implementation agents. Quality comes from using the right tool at the right time.
Every iteration should leave skills, agents, and rules BETTER than when it started.
Improvement is not optional — it's part of the work.
